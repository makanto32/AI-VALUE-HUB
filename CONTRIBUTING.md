# Contributing to AI Value Hub

Thank you for helping improve this reference implementation. Contributions are accepted through GitHub issues and pull requests.

## Before you contribute

- Search existing issues and pull requests to avoid duplicate work.
- Open an issue before making a substantial architectural or behavioral change.
- Do not include Microsoft-confidential information, customer data, credentials, tenant identifiers, or third-party material that you cannot license.
- Use synthetic data in tests, screenshots, and examples.
- Clearly distinguish implemented behavior from proposed or roadmap behavior.

## Development workflow

1. Fork the repository and create a focused branch.
2. Follow the existing Python, React, Bicep, and documentation conventions.
3. Add or update tests for behavior changes.
4. Run the relevant tests and builds locally.
5. Open a pull request that describes the change, validation evidence, security impact, and documentation impact.

By submitting a contribution, you agree that it can be distributed under the repository's [MIT License](LICENSE). You must have the right to submit all included code and content.

## Documentation contributions

Write new public guidance in English. Use relative links for repository content, link to official Azure documentation for service behavior, and avoid claims of official Microsoft endorsement or support.

Content proposed separately to the Azure Architecture Center is subject to that repository's contributor agreement, editorial review, and content licenses.

## Reporting security issues

Do not report vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md).
