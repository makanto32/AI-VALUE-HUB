# Security Policy

## Supported versions

This repository is a community-maintained reference implementation. Security fixes are applied to the latest revision on the default branch only. No release currently has a production support commitment or service-level agreement.

## Report a vulnerability

Do not open a public issue for a suspected vulnerability or include secrets, personal data, or customer data in a report.

Use the repository owner's private contact method on GitHub or GitHub Private Vulnerability Reporting, when available. Include:

- the affected component and revision;
- reproduction steps or a proof of concept;
- the potential impact;
- suggested mitigations, if known.

The maintainer will acknowledge the report when possible, assess scope, and coordinate disclosure after a fix or mitigation is available. This is a best-effort process, not a guaranteed response timeline.

## Deployment responsibility

Operators are responsible for threat modeling, identity configuration, network isolation, secret rotation, data classification, regulatory compliance, dependency scanning, and incident response before deployment. Demo credentials and local persistence are not suitable for production.
